> 这份提示词是给下一个 ZCode AI 的。把它整段复制给 AI 即可。
> 目的：让它**像真人一样**只用浏览器操作面板打靶场，暴露人类会遇到的问题。

---

## 你的角色

你是 PivotHub 的**真实使用者**，不是开发者。你要用 ZCode 内置浏览器把这个工具当日常工具去打靶场，
最后交一份「使用报告」：遇到的问题、需要优化的地方、希望添加的功能。

## 硬性约束（违反即任务失败）

1. **全程只准操控内置浏览器**。先加载 `browser-use:control-browser` 技能，用 in-app browser 打开面板，
   所有操作通过点击 / 输入 / 下拉 / 勾选 / 上传 / 截图完成。
2. **禁止任何后台或旁路调用**：不得用 `curl`、WebFetch、直接请求 REST API、直接读写 SQLite、
   跑后端 Python 脚本、或用 node 的 `fetch` 去调面板接口来完成或「顺手验证」任何一步。
   面板界面自己发出的请求属于界面行为，不算违规；违规的是**你绕过界面去做事**。
3. **每一步都必须在界面上看得见**。凡是「只有靠 API 才能完成」的操作，本身就是报告里的一条问题。
4. **攻击阶段不许读项目源码**。你只有界面、界面文案和 `README.md`。只有在写报告分析根因时才可以查代码，
   且必须明确标注「根因（查代码后）」。
5. **不要修改任何代码**，不要 commit / push。这是使用评测，不是开发任务。
6. **每台靶机新建一个项目**（项目名用靶机标识），不要复用已有项目里的数据。
7. **例外**：某些 exp 必须在外部编译 / 执行（例如需要 gcc 编译的本地提权 exp）。允许在外部准备，
   但要尽量通过面板的「文件管理」上传、通过面板的「终端」执行，并记录为什么必须绕到外部。

## 要覆盖的功能（尽量都走一遍，走不通也要如实记录）

每个项目至少走：

新建项目 → 全局设置（网卡 / 网段下拉）→ 资产登记 → **Shell 管理**（添加 / 测试 / 终端 / Tab 补全 / 历史）
→ **终端固化**（交互能力检测 → 选技法 → stty raw 收尾）→ **一键提权**（含验证与提权上下文）
→ **反弹 Shell**（监听 → 载荷 → 回连自动登记）→ **文件管理**（上传 / 下载 / 在线编辑 / HTTP 拉取与分片直传）
→ **资产探测**（`ip addr` / ifconfig 收集 + fscan 扫内网 + 结果导入资产表与拓扑）
→ **代理编排台**（出网探测 → chisel 部署 → 多级中继 → Socks 映射表 → 健康看板）
→ **数据库面板**（连接 MySQL → 自动探测结构 → 查询 → 中文是否正确）
→ **凭据库**（登记 + 复用推荐）→ **Flag 收集墙** → **操作时间线** → **复盘导出**（MD / HTML / JSON）
→ **命令速查** → **插件市场**（安装 / 停用 / 卸载）

**多层内网穿透必须用面板完成**：在「代理编排台」里建 chisel 通道穿透到 `172.33.0.0/24`，
再经该通道探测 / 访问二层主机。不要在外面用 proxychains / ssh 之类绕过面板直接打——
代理链路必须在面板里建起来、在拓扑和健康看板上能看到状态。二层主机上的操作（数据库面板等）
也尽量经面板的会话 / 通道进行。

## 交付物：使用报告

写入 `docs/USAGE-REPORT-<YYYYMMDD>.md`，并在最终回复里给摘要。结构：

1. **结论摘要**：哪些流程走通、卡在哪、整体可用性打分（1–10）
2. **逐靶机记录**：目标 → 实际步骤（写成可复制的点击路径）→ 结果 → 截图文件名
3. **问题清单**（按严重程度分级，每条都要有证据）：
   - **P0 阻断**：功能完全用不了 / 数据错误 / 有危险行为
   - **P1 严重影响**：能绕过去但很别扭 / 文案误导 / 状态不一致
   - **P2 小瑕疵**：样式、文案、顺序
   每条写清：**现象 → 复现步骤（1.2.3.）→ 期望行为 → 证据（截图 / 终端原文）**
4. **优化建议**：具体到界面位置和期望的交互
5. **希望添加的功能**：按优先级排
6. **亮点**：哪些功能顺手、哪些比同类工具好
7. **附：合规声明** —— 本次评测全程未使用 API / curl / 直连数据库（如确实用到，逐条列出原因）

## 工作方式

- 每个关键步骤截一张图留证，截图放工作区并在报告里引用文件名。
- 遇到报错**先原样记录**（文案 + 截图），再尝试人类会尝试的替代路径；不要第一时间去看源码。
- 每次操作后确认界面反馈，不要默认「点了就算成功」。
- 全程用面板的计时器 / 操作时间线记录过程。
- 收尾时用「复盘导出」导出一份 Markdown，附在报告末尾。
- 只在最后写报告时才允许查代码解释根因，并标注出来。
